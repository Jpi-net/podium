# Contributing

Thanks for helping. Issues and pull requests are welcome.

## Develop

Run Claude Code with the plugin loaded from your clone; it reloads when a file changes:

```bash
claude --plugin-dir plugin --debug
```

Before opening a pull request, from the repository root:

```bash
claude plugin validate .
claude plugin validate plugin
claude plugin test plugin
for f in plugin/skills/setup/templates/hooks/*.mjs; do node --check "$f"; done
```

Type-checking: once the engine has loaded the plugin, it writes `plugin/.claude-plugin/types/` (ignored by git), and `tsc -p plugin` checks the hooks against the exact API of your Claude Code version.

Only `plugin/` is published. `.claude/` is the development setup generated by maestro on itself and is not shipped.

## Layout

| Path | What it holds |
| --- | --- |
| `.claude-plugin/marketplace.json` | Makes the repository installable as a marketplace (source `./plugin`) |
| `plugin/.claude-plugin/plugin.json` | Plugin manifest |
| `plugin/hooks/register.tsx` | Entry point: commands, event hooks, the `/maestro-stage` panel |
| `plugin/hooks/project.ts`, `rules.ts` | Reading `.claude/maestro.json` and the project's `.claude/`, rule checks |
| `plugin/hooks/scene.ts`, `canvas.ts`, `sprite.ts`, `font.ts`, ... | The pixel-art scene drawn in the panel |
| `plugin/skills/setup/` | The `/maestro` skill: `SKILL.md`, `references/`, `templates/` |
| `plugin/types/index.d.ts` | The contract of the values kept in session state |
| `plugin/tests/` | Tests run by `claude plugin test plugin` |
| `plugin/README.md` | Full user documentation, shipped with the plugin |
| `.claude/` | Maestro's development setup for this repository (not shipped) |
| `.github/` | CI and templates |

## Conventions

- TypeScript, two-space indent, LF; code lives in classes with static members.
- Every change ships with a test.
- User-facing text is English.
- Commits: short imperative subject (`Add the gradle toolchain to verification guesses`).
